# P0 — CONVERSATION AUTHORIZATION

المشكلة الحية:

```text
requests_officer:
GET /api/conversations              → 200 []
GET /api/conversations/1/messages   → 200 []
GET /api/admin/conversations        → 200 []

driver:
GET /api/conversations              → 200 []
GET /api/conversations/1/messages   → 200 []
GET /api/admin/conversations        → 200 []
```

بينما `/api/auth/me` أظهر أن صلاحيات هذه الحسابات فارغة، وبالتالي هناك bypass في authorization.

## المطلوب

راجع authorization الفعلي في:

* Express conversation routes
* PHP production API
* أي middleware/permission mapping
* أي fallback يسمح بقراءة المحادثات

لا يكفي إضافة authentication فقط؛ المطلوب **role/permission enforcement فعلي**.

النتيجة المطلوبة:

```text
Unauthenticated → 401

requests_officer → 403
driver            → 403
```

على المسارات التي لا يملكون صلاحية الوصول إليها.

وفي نفس الوقت:

```text
manager
customer_service
```

يجب أن يحتفظا فقط بالصلاحيات المقصودة لهما.

**لا تمنع customer_service من وظائف المحادثات التي يحتاجها النظام.**

### مهم

اختبر:

```text
/api/conversations
/api/conversations/:id/messages
/api/admin/conversations
```

بكل role موجود فعليًا.

لا تعتمد على أن القائمة الحالية `[]`.

اختبر authorization نفسه.
