# FINAL EXECUTION DIRECTIVE — CLEANFLOW / SABAIK ALMASA

أنت الآن تعمل على **الحالة الحالية للمشروع بعد تنفيذ الجولة السابقة من الإصلاحات**.

ممنوع البدء من الصفر، وممنوع إعادة تنفيذ إصلاحات سبق تطبيقها دون التحقق أولًا من حالتها الحالية.

الهدف النهائي الوحيد:

> **إغلاق جميع الثغرات الحرجة + إغلاق مشاكل SEO المؤكدة + إثبات parity بين Runtime / SSG / Sitemap / Production Build / Structured Data / Business Identity + تنفيذ Audit شامل لكل أنواع الصفحات + إصدار حكم نهائي صريح: READY FOR PRODUCTION أو NOT READY FOR PRODUCTION.**

لا تعتبر نجاح `build` أو `typecheck` وحده دليلًا على الجاهزية.

# 0. قاعدة العمل الإلزامية

ابدأ أولًا بـ:

1. فحص `git diff` / حالة الملفات الحالية.
2. معرفة ما تم تغييره في الجولة السابقة.
3. تشغيل الاختبارات الموجودة قبل تعديل أي شيء.
4. لا تعكس أي إصلاح صحيح موجود بالفعل.
5. لا تنظف output يدويًا فقط؛ أصلح **المصدر الذي يولده**.
6. لا تدّعي أن مشكلة تم حلها إلا إذا أثبتها اختبار قابل لإعادة التشغيل.
7. لا تخترع نتائج production لم يتم اختبارها.
8. إذا تعذر إثبات نقطة، اكتب صراحة:
   `UNVERIFIED`
   ولا تحولها إلى PASS.

الملف السابق يوضح أن الجولة السابقة وصلت إلى مرحلة التحقق النهائي لكنها توقفت بسبب quota، وبالتالي هذه الجولة هي **Completion + Verification Pass** وليست إعادة بناء من الصفر. آخر نقطة موثقة كانت وجود مشكلتين متبقيتين: content gate ومسار PHP upload.

# P14 — ممنوعات

ممنوع:

1. القول "تم الحل" بدون test evidence.
2. اعتبار build ناجحًا = production ready.
3. اعتبار similarity = duplicate content تلقائيًا.
4. اعتبار 145 duplicate canonical groups = Google penalty.
5. اعتبار `gl=EG` خطأ SEO تلقائيًا.
6. اعتبار غياب Sitemap directive في robots.txt مشكلة بحد ذاتها.
7. حذف redirects القديمة عشوائيًا.
8. تنظيف generated HTML بدل إصلاح المصدر.
9. تغيير business data بالتخمين.
10. إزالة محتوى صحيح فقط لإرضاء content gate.
11. تخطي PHP لأن Express آمن.
12. تخطي production package لأن development server يعمل.
13. إخفاء failures تحت "minor".
14. إصدار READY مع وجود `UNVERIFIED` في نقطة حرجة.

# FINAL RESPONSE FORMAT

عند الانتهاء، لا تعطِ ملخصًا إنشائيًا.

أعطني تقريرًا تنفيذيًا يحتوي بالترتيب:

## 1. FINAL VERDICT

واحد فقط:

`READY FOR PRODUCTION`

أو:

`NOT READY FOR PRODUCTION`

## 2. What was already fixed

اذكر الإصلاحات التي كانت موجودة قبل أن تبدأ، وما الذي تحققت منه.

## 3. What you changed

كل تعديل جديد مع:

* file
* function/section
* reason
* result

## 4. Security results

PASS/FAIL لكل P0.

## 5. SEO results

PASS/FAIL لكل P1-P9.

## 6. Exact final numbers

اذكر الأرقام الفعلية من **آخر build**:

* HTML count
* index/follow count
* noindex count
* sitemap URL count

* redirects
* articles

* neighborhoods
* containers

لا تكتب "tested" فقط.

`NOT READY FOR PRODUCTION`

`READY FOR PRODUCTION`
