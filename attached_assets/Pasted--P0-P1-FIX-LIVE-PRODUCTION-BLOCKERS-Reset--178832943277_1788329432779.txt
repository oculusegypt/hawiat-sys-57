# P0 — SECURITY

## 1. أصلح `/api/auth/me` caching فورًا

المشكلة المثبتة:

```text
/api/auth/me
```

بدون cache-buster كان يعيد نفس استجابة المدير حتى مع token مختلف/خاطئ.

المطلوب:

* endpoint يجب ألا يكون قابلاً للتخزين المشترك.
* أضف/ثبت:

```http
Cache-Control: no-store, private
```

* راجع أيضًا طبقة Hostinger/Apache/PHP وأي caching أمام `/api/*`.
* تأكد أن response لا يمكن مشاركته بين Authorization headers مختلفة.

### LIVE acceptance test

بدون أي query parameter:

1. Token A → هوية A.
2. Token B → هوية B.
3. Invalid token → `401`.
4. No token → `401`.
5. كرر الطلبات بترتيبات مختلفة للتأكد أن الرد السابق لا يتم reuse.

**إذا ظهر رد مستخدم سابق لمستخدم آخر = FAIL مباشر.**

---

## 2. أغلق conversation endpoints

المثبت حيًا:

```text
GET /api/conversations → 200 []
GET /api/conversations/1/messages → 200 []
```

بدون authentication.

هذا غير مقبول حتى لو كانت البيانات الحالية فارغة.

المطلوب:

* `/api/conversations` → auth مطلوب.
* `/api/conversations/:id/messages` → auth مطلوب.
* طبّق authorization حسب role/ownership، وليس authentication فقط.
* لا تسمح لأي مستخدم بالوصول إلى محادثات مستخدم آخر.

### LIVE tests

بدون token → `401/403`.

Token customer/service role → تحقق من حدود الوصول.

Admin/authorized role → الوصول المسموح فقط.

Invalid token → `401`.


**ممنوع 200 + Homepage.**

بعد الإصلاح تحقق من:

* status
* title
* description
* H1
* canonical
* robots
* JSON-LD
* content uniqueness

## 4. أصلح Soft 404

هذا الاختبار يجب أن يصبح:

```text
GET /definitely-not-a-real-page-2026/
→ 404
```

وليس:

```text
200 Homepage
```

راجع fallback في Hostinger/Apache/PHP/SPA routing.

يجب ألا يتحول أي URL غير معروف إلى Homepage بـ 200.

# P0 — AL-SHIFA

## 5. أصلح `/areas/حي-الشفا/` و `/areas/al-shifa/`

حاليًا redirect مشوه إلى:

```text
%D8%AD%D9A-%D8%A7%D94%D8%B4%D91%D8%A7
```

ثم Homepage.

المطلوب:

* حدد canonical route الصحيح لحي الشفا.
* أصلح URL encoding/decoding.
* أصلح redirect mapping.
* تأكد أن route يصل إلى صفحة حي الشفا الفعلية.
* لا تجعلها Homepage.
* حافظ على حالة `noindex` إذا كانت هذه هي الحالة المعتمدة في الـ build الحالي.

### LIVE acceptance

اختبر كلا المسارين:

```text
/areas/حي-الشفا/
/areas/al-shifa/
```

ويجب أن ينتهيا إلى **صفحة حي الشفا الصحيحة** وليس Homepage.
