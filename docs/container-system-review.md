# مراجعة نظام الحاويات وإعادة تنظيمه

## نطاق النظام

النظام يبدأ من /admin/container-system، لكنه يمتد إلى صفحات تشغيلية مستقلة وملفات تفصيلية وطباعة. الواجهة الأساسية تجمع سجلات متعددة الأنواع في قاعدة بيانات واحدة، بينما تنفذ بعض العمليات الحساسة عبر مسارات API مخصصة ومعاملات ذرية وسجل تدقيق.

## دورة الحياة الفعلية

### العميل والعقد

1. مراجعة بيانات العميل ثم اختيار ملفه وموقع تابع له.
2. إنشاء العقد مع نوع الحاوية والأصل أو نموذج بند الإيجار، واعتماد السعر والضريبة والشروط.
3. يحفظ مسار إنشاء العقد الروابط الأساسية ومفتاح منع التكرار. للعقد المرتبط بأصل، ينشأ التخصيص وأمر العمل المجدول ضمن مسار واحد.
4. أمر العمل يتبع حالات الإسناد والقبول والتنفيذ والوصول والإكمال. الإكمال المرتبط بالحاوية يتطلب بيانات الإثبات المحددة، ثم يسجل الحركة ويزامن حالة العقد والأصل وسجل التدقيق.
5. بعد التسليم يمكن إنشاء مهمات التفريغ أو السحب. لا يسمح الاسترجاع أو الإقفال مع وجود مهمة مفتوحة.
6. يتم التحصيل من كشف العقد مع توزيعه على الفواتير. لا يسمح إقفال العقد قبل الاسترجاع، وإنهاء المهام، وتسوية الرصيد، وترحيل الفواتير المرتبطة.

### حالات العقد والأصل

- حالات العقد تشمل المسودة، بانتظار الاعتماد، الصادر، النشط، المعتمد، تم التسليم، تم الاسترجاع، مرفوض، منتهي ومغلق.
- الأصل ينتقل عملياً من متاح إلى محجوز عند التخصيص، ثم مؤجر عند التسليم، ثم يعود متاحاً بعد الاسترجاع أو الإغلاق.
- عمليات التسليم والاسترجاع الآلية تحدث العقد والأصل والحركة والتدقيق داخل معاملة واحدة.
- عقود النظافة التي لا تحتاج إلى أصل حاوية لا تنشئ مهمة تسليم للحاوية.

### أوامر العمل

المسار التشغيلي للسائق هو: assigned ثم accepted ثم started ثم en_route ثم arrived ثم completed. يمكن رفض المهمة قبل تنفيذها. إكمال مهمة حاوية يسجل دليل التنفيذ، ويحدّث العقد والأصل والحركة والسجل المرتبط.

### المالية

التسوية تربط دفعات العميل بالعقد والفواتير، وتدعم مفتاح منع التكرار وتوزيع الدفعة على أكثر من عقد. الإقفال يعتمد على القيود المرحلة وحالة الفواتير والرصيد النهائي، بينما التصحيح المالي يتم بحركات عكسية موثقة بدلاً من تحرير القيود المرحلة.

### الأسطول والمخزون والحوكمة

- متابعة الأسطول تجمع حالة المركبة والسائق والصيانة والتصاريح وقراءات الزيت والوقود، مع تنبيهات الصلاحية والاستحقاق.
- المخزون مقسم إلى تعريف الأصناف والأحجام والمستودعات والمشتريات والمرتجعات والصرف.
- سجل التدقيق يسجل التغييرات التشغيلية والمالية، والتقارير تعرض مجموعات المبيعات والتحصيل والمصروفات والأسطول والمخزون.

## ملاحظات المراجعة ذات الأولوية

1. سير عمل المعاينة كان يشغل الواجهتين من دون تشغيل خدمة الـAPI التي تقرأ قاعدة البيانات. أضيفت خدمة الـAPI إلى سير العمل مع انتظار جاهزية المنفذ 8080، وأعيد تشغيلها في مساحة العمل.
2. كان التنقل الداخلي طويلاً ومقسماً حسب السجل أكثر من ترتيب العمل؛ كما ظهر أسفل المحتوى على الهاتف. أُعيد ترتيبه حسب رحلة العمل وأضيف اختيار مجال وقسم للهاتف مع قائمة أولويات مباشرة.
3. تغيير القسم كان يحدث داخل الحالة فقط، فلا يعكس رابط الصفحة القسم المحدد. أصبح اختيار القسم يحدّث معامل view لدعم المشاركة والرجوع في سجل المتصفح.
4. نافذة العقد كانت تعرض الأزرار دون ملخص بصري للمراحل. أضيف مسار يوضح التسجيل والاعتماد والتسليم والاسترجاع والتسوية والإغلاق.
5. نافذة العقد كانت تقول إن النظام سينشئ موعداً حتى مع أن المسار ينشئ أمر عمل مجدولاً فقط لعقود الحاويات. عُدلت الرسالة لتطابق التنفيذ، مع توضيح استثناء عقود النظافة.
6. كانت تظهر إجراءات تسليم لا يقبلها الـAPI للمسودة أو العقد المنتهي، وزر تحويل لمديونية لا ينفذ عملية. قُيدت أزرار التسليم بالحالات المدعومة وأزيل الزر غير المنفذ.
7. ربط المهمة المفتوحة في بعض تفاصيل العميل أو الأصل كان يقارن معرّفات اختيارية مفقودة على أنها صفر، ما قد يربط مهمة غير ذات صلة. أصبح الربط يتطلب معرّف عقد أو أصل صالحاً.
8. كانت دورة العقد تخفي أسباب رفض الإجراء خلف رسالة عامة. أصبحت قواعد العمل المتوقعة تُعاد برسالتها للمستخدم الإداري، بينما تبقى أخطاء الخادم الداخلية برسالة عامة. كما أصبح رفض الاعتماد لغير المدير يعاد كرفض صلاحية واضح.

## الهيكل المقترح للصيانة والتوسع

- إبقاء التنقل وترتيب الأولويات منفصلين عن صفحة المركز في ContainerSystemNavigation.tsx.
- فصل كل مجال كبير لاحقاً إلى وحدات واجهة وخدمات بيانات مستقلة: العقود والعملاء، التشغيل والأسطول، المالية، والمخزون.
- اعتماد نمط واحد للنوافذ: عنوان يوضح المهمة، سياق السجل، خطوات مرئية للنماذج متعددة المراحل، ورسالة واضحة للمانع أو الخطأ.
- إبقاء الحالات الحساسة والتحديثات المالية في API معاملاتية؛ الواجهة تعرض سبب المنع ولا تحاول تجاوز قواعده.
- استخدام سجلات التدقيق والروابط العلائقية كمصدر التاريخ، وعدم تعديل الحركة المالية أو التشغيلية المرحلة مباشرة.
